# Image, caption, and metadata preprocessing

This note describes the implemented pipeline in
[`02_preprocess_images.ipynb`](../02_preprocess_images.ipynb),
[`03_captions_metadata.ipynb`](../03_captions_metadata.ipynb),
[`04_embeddings_index.ipynb`](../04_embeddings_index.ipynb), and
[`common.py`](../common.py). It reflects the code used for the frozen release.

## Images: audit, EXIF, RGB, and stored resize

In notebook 02's `process` function, each source image is first opened and
`verify()` is called to catch invalid/truncated files. It is reopened and
loaded, its EXIF orientation is recorded, then `ImageOps.exif_transpose`
applies the orientation correction. The result is converted to RGB.

The configured `image.max_side` in `config.yaml` is 512. If either side exceeds it, both
dimensions are scaled by the same factor (`512 / max(width, height)`), rounded
to at least one pixel, and resized using Pillow `Image.LANCZOS`; this preserves
aspect ratio. The resulting image is saved as JPEG at configured quality 95
with `subsampling=0`, under `artifacts/images_rgb/<split>/<12-digit-id>.jpg`.
These stored images are already EXIF-corrected RGB.

The audit computes pixel statistics from a 64×64 `Image.BILINEAR` sample:
brightness, contrast, colorfulness, sharpness, darkness, and named dominant
colors. SHA-256 is computed from the raw source file. The perceptual hash is a
difference hash, recorded in `images.csv` along with image dimensions, source
mode, EXIF correction, resize flag, output path, and duplicate flag.

## Encoder-specific model preprocessing

`HFEncoder` in notebook 04 opens the stored RGB images and passes them to the
Hugging Face processor selected by model:

- CLIP and SigLIP use `AutoProcessor` and the model's `get_image_features`.
- DINOv2 uses `AutoImageProcessor`, then the CLS token
  (`last_hidden_state[:, 0]`) as the image feature.
- The feature arrays are converted to `float32` and L2-normalized before
  caching.

The Python code delegates resize/crop/normalization to each checkpoint's
processor; it does not hard-code separate resize dimensions for all three
models. The processor configuration is not included in the frozen release, so
per-model processor resize/crop dimensions cannot be independently read from
the release files.

For text, CLIP tokenization uses truncation at 77 tokens with dynamic padding;
SigLIP uses max-length padding and truncation at 64 tokens. Text features are
also converted to `float32` and L2-normalized.

## Caption fields and cleaning

The captions/metadata notebook sorts captions for each image by COCO caption ID
and retains the first five. In `kb_captions.jsonl`, it preserves the source text
as `caption_raw`, stores a normalized `caption_clean`, and counts tokens from
that cleaned form in `n_tokens`. Evaluation files
`eval_refs_val.jsonl` and `eval_refs_test.jsonl` keep `caption_raw` only; they
are not used as retrieval data.

`common.clean_caption` performs these operations in order:

1. strip leading/trailing whitespace and lowercase;
2. replace characters that are neither word characters, whitespace, nor
   apostrophes with a space;
3. remove a single quote surrounded by spaces;
4. collapse repeated whitespace and strip again.

The raw field is not overwritten by this cleaning. QC's caption-overlap test
compares cleaned strings, not the raw source strings byte-for-byte; see
[`reports/leakage_audit.md`](../reports/leakage_audit.md).

## Metadata extraction

Notebook 03 joins selected split records to COCO instance annotations and
captions. It ignores crowd annotations. For each object it records the COCO
category ID/name and supercategory, normalized bounding box, fraction of image
area, and size label (`small` below 0.02, `medium` below 0.15, otherwise
`large`). Boxes are clipped to image bounds. The largest objects are processed
first; pixel dominant color is estimated for up to the first eight objects
with area fraction at least 0.01.

Top-level metadata includes object/category counts, supercategories,
complexity, context, day/night, brightness/colorfulness, dominant image colors,
objects, relations, caption attributes, and source labels. Complexity is
derived from object count using `common.py`: simple 1–2, medium 3–5, complex
6–9, crowded 10 or more. Context is assigned from indoor/outdoor COCO
supercategories. Day/night uses the preprocessing brightness flag.

Spatial relations (`inside`, `contains`, `on_top_of`, `overlapping`, `left_of`,
`right_of`, `above`, `below`) are derived geometrically from normalized boxes
among at most the eight largest objects; they are not generated by a semantic
scene-graph model. Caption attributes are extracted from a fixed lexicon of
color, size, material, state, and shape words and are stored only for KB
images. Validation/test caption-derived attributes are `null`, avoiding use of
evaluation captions as metadata features.

Object labels for all three splits are COCO ground truth. Consequently, the
validation/test object metadata is an oracle for retrieval evaluation; the
optional `03b_detect_objects.ipynb` path supplies predicted DETR detections for
more realistic query metadata.
